# 摄像头骨骼识别与姿势参考库

本次只改摄像头识别。页面结构、样式、视频/照片识别、图谱、雕塑切换和丝带动画均保留。

## 模型与数据

- 摄像头先使用 MediaPipe Pose Landmarker Full，与前期本地视频分析使用过的 Full 模型相同。缺少可靠身体关节时，使用前期视频分析的 YOLO26s Pose 备用检测。两套权重均未重新训练。
- 模型保存在 `assets/camera/pose_landmarker_full.task`，摄像头不再从 Google Storage 下载模型。JavaScript/WASM 仍使用原来的官方 `@mediapipe/tasks-vision@0.10.14`。
- 官方模型来源：<https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_full/float16/1/pose_landmarker_full.task>。
- 模型 SHA-256：`4eaa5eb7a98365221087693fcc286334cf0858e2eb6e15b506aa4a7ecdcec4ad`。
- YOLO 使用同一个已安装的 `yolo26s-pose-group.pt` 权重，重新导出为摄像头输入 `1×3×480×640`、输出 `1×32×57` 的 ONNX。原视频分析模型保持原样。只识别主要前景人物。
- `assets/camera/yolo26s-pose-camera.onnx` 约 21.1 MB；137 个权重张量以 FP16 存储、运算前转换为 FP32，计算和输出仍是 FP32。实际图片及镜像测试与未压缩导出的关节差异均小于 0.03 个输入像素，空白图片没有检出人物。该测试不是准确率评估。
- 摄像头 ONNX SHA-256：`b3936aca5ba58edea5a504903f1b28280367e8fea25bf9fedf34874de5be26a7`。
- YOLO 使用官方 `onnxruntime-web@1.23.2` 的单线程 WASM；不要求站点添加跨源隔离响应头。模型存在仓库内；SDK/WASM 仍从 jsDelivr 加载，首次使用增强检测需下载模型和运行时。
- YOLO 来源及许可：<https://docs.ultralytics.com/models/yolo26/>、<https://www.ultralytics.com/license>；遵循 Ultralytics 模型的 AGPL-3.0 许可条件。运行时来源：<https://onnxruntime.ai/docs/tutorials/web/>。
- 47 条已完成、具有 `validation.json` 的视频骨骼结果，来自 YOLO 17 点和 MediaPipe 33 点分析，统一为 13 个共同关节。
- 每隔约 0.75 秒抽取候选，检查关节置信度、存在分数、身体比例及画面范围；49,462 个人物帧候选中保留 23,154 个，再去重并限制每类/每个视频的数量。
- `data/camera-pose-library.json` 包含 1,327 个参考：站立 400、坐 366、蹲 237、斜倚 218、水平 106。行走继续使用时间序列中的腿部运动判断，不给单帧视频样本添加“真实行走”标签。
- 参考库只包含归一化骨骼坐标、分数、视频标题及来源帧；不包含原视频、摄像头画面或本机路径。

**这些姿势标签由保守的几何规则生成，是候选参考，不是人工标注的训练真值。增加参考不等于完成监督训练，也不证明识别准确率。**

## 识别流程

1. 打开摄像头后，才加载 Full 模型和参考库。
2. 优先在后台 Worker 中识别；MediaPipe 的 GPU 初始化失败时尝试 CPU，仍失败则尝试 YOLO；身体检测不完整时也尝试 YOLO。浏览器不支持后台方式时使用主线程兼容方案，速度取决于设备。
3. 用可见关节构造髋部居中、按躯干长度归一化的二维描述，支持左右镜像；不把 YOLO 二维坐标当成 MediaPipe 三维坐标。
4. 参考库只辅助原来的六类姿势判断，不覆盖高置信度但不一致的三维判断，也不新增雕塑类别。
5. 连续保持可靠姿势至少 2 秒并获得至少 3 次一致检测才确认。允许较慢的 CPU 检测间隔，间隔超过 2 秒会重置。相同类别内改变手势或明显改变造型，可再次确认；人物消失或关键关节不可靠时立即清空保持计时。
6. 继续调用原来的 `addCamPose` / `applyDay`。原有雕塑选取和切换效果、十个序列位置上限均保持。

识别分数是模型与匹配分数，不是经校准的准确率。只拍到上半身时，站与坐可能无法可靠区分，会通过原摄像头状态栏提示更多腿部入镜，不猜测缺失关节。

## 维护与验证

```powershell
python tools/build_camera_pose_library.py --analysis-root "D:\G4 posture\已分析"
node tools/check_camera.mjs
node tools/check.mjs
```

`check_camera.mjs` 的 22 项检查包括六类已知姿势、尺度/镜像、遮挡、同类不同造型、2 秒确认、较慢检测的确认、YOLO 关节映射、人物消失及重新开启摄像头的竞争条件，并核对摄像头以外的代码和界面未变化。

实际视频中的一张坐姿图片被 MediaPipe Full 漏检，但 YOLO 备用检测恢复了 12 个主要身体关节；官方 ONNX Runtime Web WASM 在 Node 环境中也正确检出坐姿，单次推理约 0.45 秒（本机，单线程，非浏览器端到端计时）。这证明该样本可通过备用路径，不能代表全部访客的识别准确率。

当前受限环境无法启动 Edge 测试浏览器（进程启动后管道错误），所以浏览器 Worker、摄像头连续确认及手机布局的端到端测试尚未通过。提供本机预览检查入口，运行后记录实际结果，再发布。此限制不等于网页测试失败。

基线版本 `14f162f` 的通用 `check.mjs` 已存在“旧 `04d-va-hall-scan.js` 未列入 PARTS”的错误；实际页面引用带版本号的扫描模块。本次未改扫描模块或加载列表，摄像头检查另行验证实际 PARTS 拼接后的完整模块语法。

发布前还应通过浏览器实际模型加载与摄像头测试。推荐：正面全身站立、举手、遮挡、坐、蹲、斜倚；每个姿势保持两秒；同类换造型、离开后返回、关闭后重新打开。检查原雕塑和丝带动画，及手机竖屏。摄像头和 Worker 中的帧只在浏览器内处理，不上传。
