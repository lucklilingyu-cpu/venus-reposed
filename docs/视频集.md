# Skeleton Video Collection

在“视频 / 照片”里，视频集放在“骨骼图集”与其校正工具下方。选择视频会读取对应的实际骨骼关节点，生成时间顺序中的代表姿势，并调用文字日记现有的 `applyDay(day, { source, fresh: true })` 完成雕塑匹配、棋盘移动和雕塑升起动画。文字日记、照片识别/校正、摄像头和雕塑动画函数保持原样。

每次选择视频都调用现有的 `flyHome()` 返回展厅宏观视角，与照片展示结束后的全景相同；切换时清除上一次照片近景的返回计时器和环绕图片。视频按自己的数据生成结果，展示如“站立 → 蹲 → 水平”的实际识别序列，不强制填满六种类别。快速切换视频时保留最新选择；切换到文字日记、照片或其他输入会取消尚未应用的视频分析。

本集包含七条 Venus / Aphrodite、两条 Medusa 和一条 Venus / Nephthys 主题的完整分析结果，保留原有骨骼叠加和音轨。网页副本使用 H.264 / AAC、最高 1280 × 720 像素、30 fps，并把 MP4 索引前置。新增视频按原比例缩放，保留完整画面；原有九条网页文件和 D 盘原始分析结果保持原样。所有视频只有在选中后才开始加载，首页仅请求目录与按需显示的缩略图。

为减少网络缓冲，默认播放 `video/pose-gallery/stream/` 中完整的流畅副本：最高 854 × 480，H.264 视频上限 450 kb/s、AAC 64 kb/s，索引前置。十条共约 138 MB，相比原高清文件约 395 MB 减少 65% 的播放数据量。播放器提供 Smooth / HD 选择，切换保留时间位置，不重新生成雕塑；下载链接仍指向原高清文件，所有旧视频文件保持原散列。

只给选中的视频设置 `preload=auto`，不预下载其他九条。读取骨骼数据后，优先让选中视频缓存至少约三秒，再调用原有雕塑生成函数，减少初始视频下载与新模型加载争用；缓存等待有八秒上限且可随切换取消。播放和雕塑动画仍可同时进行，原有动画、模型精度与其他视图保持原样。转圈时显示实际缓存秒数，便于区分下载等待与姿势分析。

缓存检测依据浏览器的 [`buffered`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/buffered) 区间；[`preload`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preload) 是浏览器加载提示，不能保证网络流畅。发布前浏览器测试另外模拟约 0.92 Mb/s、150 ms 延迟的连接，在视频开始后测量连续播放十二秒，并观察视频播放与雕塑实际位置变化是否重叠。这个受控测试不代表所有地区网络情况。

- `Explicit goddess theme`：Bananarama 的歌曲直接命名 Venus。
- `Official styling association`：第一条 7SENSES 演出由 [SNH48 官方报道](https://www.snh48.com/html/snh/allnews/zixun/202201/5947.html) 比拟为维纳斯，但报道没有确认改编自某一件雕塑。

- `Mythological imagery`：第八条采用 Medusa 相关石化意象的解读，见 [NME 评论](https://www.nme.com/reviews/kiss-of-life-midas-touch-review-3616351)。评论提出的视觉解读不等于官方确认的雕塑编舞来源；Midas 与 Medusa 是不同的神话人物。第九条是同曲舞蹈的视觉对照。
- `Explicit goddess lyrics; visual pose comparison`：第十条 Dreamcatcher《OOTD》的歌词提及 Venus 与 Nephthys，见 [Genie 歌曲与歌词资料](https://www.genie.co.kr/detail/songInfo?xgnm=104451090)。舞蹈用于姿态视觉对照，歌词命名并不证明编舞改编自某一件女神雕塑。

视频目录在 `data/pose-video-gallery.json`，网页视频在 `video/pose-gallery/`，缩略图在 `img/pose-video-gallery/`。独立脚本 `js/07b-pose-video-gallery.js` 复用现有分类和日记动画入口；新增 CSS 仅作用于视频集选择器。

`data/pose-video-sequences.json` 从这十条视频原有、已经验证的 YOLO 关键点 CSV 中整理而来。构建工具约以 8 fps 抽样，仅接受双肩、髋、膝、脚踝等主体关节完整且置信度至少 0.6 的人物；多人画面综合关节质量、身体大小、画面位置和短时间连续性选取代表人物。关节点以髋为中心、躯干长度归一化、Y 轴向上，保留二维图像估计，不宣称恢复真实三维运动。

分类使用 `js/07-inputs.js` 原有的 `classifyPose`，配合短时间稳定性筛选，按先后顺序保留最多十个代表动作片段。网页选择视频时还会用同一个分类函数复核保存的关节点，并沿用文字日记的相邻同类合并选项及 `mergeDay`，再交给原有生成函数；无需再次下载模型或重跑整段视频。每条记录包含对应网页视频的散列、原 CSV 散列、帧编号、时间与代表关节点，可追溯到原分析结果。自动分类可能受到镜头倾斜、遮挡和舞蹈动作影响，生成后仍可使用原序列卡片修改类别。

可复现的构建工具：`tools/extract_pose_video_samples.py` 读取私有输入清单，`tools/build_pose_video_sequences.mjs` 用现有分类函数整理结果。私有清单中的本地路径不会进入公开数据，也不会修改 D 盘视频或 CSV。

检查：

```powershell
node tools/check_pose_videos.mjs
node tools/check.mjs
```
